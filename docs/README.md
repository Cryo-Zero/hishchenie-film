# Документация проекта

## Канонический текущий статус

- `current/PROJECT-STATE.md` — **единственный канонический текущий статус проекта**. Начинать handoff и новый ChatGPT-чат нужно с него.

## Backend / Supabase

- `database/supabase/*-APPLIED.md` — подтверждённые уже применённые backend-состояния.
- `database/supabase/REVIVAL-R1-APPLIED.md` — зафиксированное применённое состояние REVIVAL R1.
- `database/supabase/REVIVAL-R6-APPLIED.md` — зафиксированное применённое состояние REVIVAL R6.
- SQL-файлы в `database/supabase/` — исходники миграций и служебные материалы. Наличие SQL-файла **не доказывает**, что миграция применена к production.
- `database/migrations/` — исторические миграционные заметки.

## Релизы

- `releases/p-series/` — история P14–P22, включая QA и UPDATE-документы.
- `releases/revival/` — история REVIVAL R1–R6; UPDATE и QA лежат рядом с соответствующим релизом.

P20–P22 — отвергнутые большие редизайны. Они сохранены только как история и не должны использоваться как актуальный UI baseline.

## Архив и история

- `/archive/` — исторический код и отвергнутые реализации, не являющиеся текущим runtime.
- `history/` — вспомогательные исторические документы, не являющиеся текущими требованиями.

Исторические материалы не удаляются без отдельного решения.

## Администрирование

- `admin/` — setup/roadmap-документы существующей старой REVIVAL R1 админки.

Правило для нового релиза: сохранять минимум `UPDATE` + `QA`; если требуется изменение БД — хранить исходный SQL/migration document и отдельно фиксировать подтверждённое применённое состояние в `*-APPLIED.md` после реальной проверки production.
